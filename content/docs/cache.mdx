從原理到實踐,把 FurCDN 快取調到極致。

> **TL;DR** 三條黃金原則:
> 1. **靜態資源設長 TTL + 配合版本號**,讓使用者永遠拿快取
> 2. **HTML 設短 TTL**,兼顧更新即時性
> 3. **API 不快取**(TTL=0),動態內容必須回源

## 〇、JSON 模式 & 批量 JSON

跟 WAF 對齊,每條緩存規則的「新增 / 編輯」對話框增加 **JSON 模式** Tab;
頁面頂部「自訂緩存規則」區段右上角新增 **批量 JSON** 按鈕。

### JSON 模式(單規則)

**儀表板 > 域名 > 編輯 > 緩存**,點「自訂緩存規則」區段右上角 **新增** /
任一條規則的 **編輯** 鉛筆。對話框頂端的 Tab:

- **表單**:可視化點按填欄位。
- **JSON 模式**:直接編輯整條規則 JSON。

切到 JSON 後修改、儲存:存的是 JSON 內容。
切回表單時若 JSON 解析失敗會停在 JSON tab 顯示錯誤,**表單內容不會被覆蓋**。

### 批量 JSON 匯入 / 匯出

按頁面上的 **批量 JSON**:

- **匯出**:所有「自訂」緩存規則(預設規則不匯出)序列化成 JSON 陣列,可一鍵複製。
- **匯入**:貼入 JSON 陣列,逐條 POST 新增,不覆蓋既有規則。
  - 與既有 `(matchType, matchValue)` 完全相同 → 後端回 409 拒絕,計入失敗數
  - 部分失敗會顯示失敗清單,**成功的會留下**

> 沒有「條數上限」(WAF 才有 10 條限制),你可以一次匯一打規則進去。

## 一、規則結構(完整 Schema)

每條緩存規則:

```json
{
  "name": "規則顯示名(必填,≤100 字)",
  "matchType": "extension",
  "matchValue": "jpg,png,webp,css,js",
  "ttl": 604800,
  "cacheControl": "public, max-age=604800, immutable",
  "priority": 10,
  "enabled": true
}
```

### 欄位逐項

| 欄位 | 型別 | 必填 | 預設 | 說明 |
|---|---|---|---|---|
| `name` | string | ✓ | — | 規則名(≤100 字) |
| `matchType` | enum | ✓ | `"extension"` | `extension` / `path` / `contentType` / `all` |
| `matchValue` | string | matchType≠all 必填 | — | 匹配值,語意依 `matchType` 而定(≤500 字) |
| `ttl` | int 0–315360000 | ✓ | — | 秒。`0` = 不快取;最大 10 年 |
| `cacheControl` | string | | `null` | 自訂回應的 `Cache-Control`,**覆寫源站**;留空 = 透傳源站(≤200 字) |
| `priority` | int ≥0 | | 10 | 數字小的先評估;第一條命中的規則生效,同 `priority` 時**較早建立的規則**勝出。`0` 是合法值(不會被改成 10) |
| `enabled` | bool | | true | `false` 視為規則不存在 |

### `matchType` × `matchValue`

| matchType | matchValue 格式 | 範例 |
|---|---|---|
| `extension` | 副檔名清單,逗號分隔;帶不帶前導 `.` 都可以(`js` 等同 `.js`) | `jpg,png,webp` / `.jpg,.png` |
| `path` | 含 `*` → 對路徑做 glob(`*` 匹配任意字元,含 `/`);否則 → 路徑**前綴**;單獨一個 `/` 只匹配根路徑 `/` | `/static/` / `/api/v2/*` / `/` |
| `contentType` | 對回應的 `Content-Type` 匹配,`; charset=…` 參數會被忽略;可含 `*` 萬用 | `image/*` / `application/json` |
| `all` | (不需 matchValue) | 命中該域名所有請求 |

逐條講清楚:

- **`extension`**:取 URL 路徑**最後一個** `.` 之後的部分(不含 query),只比對最終副檔名。如 `/img/cat.jpg?v=2` → `jpg`;`js` 與 `.js` 寫法等價。
- **`path`**:值裡有 `*` 就當 glob,例:`/assets/*.js`、`/img/*`(`*` 可以跨過 `/`);沒有 `*` 就是**字串前綴**,`/api/` 命中 `/api/x/y`,但 `/api` 不會命中 `/apis`;值剛好是 `/` 時**只**匹配根路徑 `/`,不再被當成「所有路徑的前綴」。
- **`contentType`**:比對回應標頭 `Content-Type`,`; charset=utf-8` 這類參數不參與比對。

### 匹配順序與 `cacheControl`

1. 同一域名下所有 `enabled` 的規則按 `priority` 由小到大排,`priority` 相同時**較早建立的規則**在前。
2. **第一條命中的規則就決定結果**,後面的規則不再評估。
3. 只有這條勝出規則的 `ttl` 與 `cacheControl` 會套用到回應;其他「也匹配」的規則不會疊加、也不會部分生效。

### 後端去重

同一域名下 `(matchType, matchValue)` 完全相同會被拒(回 409)。
要對同一目標有不同行為,靠調 `priority` 硬排是錯的做法 —— 重疊的規則只有第一條會生效,排序一動結果就變;而且 `(matchType, matchValue)` 一樣根本存不進去。
正確做法是用更精準的 `matchType` / `matchValue` 把目標拆成**互不重疊**的規則(例如用 `path` 指定明確路徑,而不是再開一條更寬的 `extension` 去跟它搶)。

<Callout title="規則只在節點回源時生效" type="warn">
TTL 與「不快取」設定只在**節點回源抓取內容時**套用;已經快取的內容不會因為你改了規則而消失。
改完規則後請到 [刷新快取](#purge) 刷新對應路徑,否則訪客在舊 TTL 到期前還是會看到舊內容。
</Callout>

## 二、快取儲存與命中流程

快取存在**每個節點自己的磁碟**上(節點之間不共享),單域名與整個節點都有容量上限,超過時淘汰最久沒被存取的 entry。節點重啟後磁碟上的快取仍在。

### 命中流程

```
請求進來
  ↓
WAF 評估 (allow/block/challenge)
  ↓
GET / HEAD 且沒有 Authorization / 非挑戰用 Cookie / 客戶端 no-cache?
  ├ 否 → 直接回源,不讀也不寫快取
  ↓ 是
磁碟有未過期的 entry? → 是:X-Cache: HIT,直接返回
  ↓ 否
回源 → X-Cache: MISS;符合快取條件就同時寫入磁碟
```

同一個快取鍵同時有大量 MISS 時,節點只讓一個請求回源,其餘請求等它寫完後直接 HIT,不會一擁而上打源站。

### Response Headers

| Header | 含義 |
|---|---|
| `X-Cache: HIT` | 命中節點磁碟快取 |
| `X-Cache: MISS` | 這次是從源站取的(包含「不可快取所以每次都回源」的請求) |
| `X-Cache-TTL: <秒>` | 僅 HIT 時出現:這份快取還剩多少秒過期 |
| `X-Cache-Node: <name>` | 哪個節點服務了這個請求 |

## 三、預設規則

新建域名時自動產生若干條 `isDefault: true` 規則,典型為:

| 規則 | matchType | matchValue | TTL | 用途 |
|---|---|---|---|---|
| 靜態資源 | extension | `jpg,jpeg,png,gif,webp,svg,ico,css,js,woff,woff2,ttf,eot,mp4,webm,mp3` | 7 天 | 長 TTL |
| HTML 頁面 | extension | `html,htm` | 5 分鐘 | 兼顧更新即時性 |
| API 不快取 | path | `/api/` | 0 秒 | 動態 API 必須回源 |

- 預設規則**可開關但不會被批量匯出**。
- 至少保留「API 不快取」,否則動態內容會被誤快取。

## 四、快取鍵設定(域名級)

每條規則決定 **是否快取與快取多久**,**快取鍵組成**則是域名級設定。

### 預設快取鍵

```
SHA256(method + host + uri + query + cacheKeyHeaders 們的值)
```

### `ignoreQueryString`

開啟後 query 不入鍵,例如版本號 `?v=20240101` 對 CDN 等同同一份。

| URL | 預設 | ignoreQueryString=true |
|---|---|---|
| `/page` | key A | key A |
| `/page?v=1` | key B | **key A** |
| `/page?v=2` | key C | **key A** |

**反例**:搜尋頁 `/search?q=apple` 跟 `/search?q=banana` 結果不同,不能忽略 query。

### `cacheKeyHeaders`

陣列,加入快取鍵的 HTTP header 名稱:

```json
["Accept-Language", "X-Device-Type"]
```

效果:不同 header 值快取為**獨立副本**。

**最佳場景**:多語言網站根據 `Accept-Language` 返回不同語言。

| 請求 | 快取鍵 |
|---|---|
| `/page` + `Accept-Language: zh-TW` | key_zhTW |
| `/page` + `Accept-Language: en-US` | key_enUS |

### 快取爆炸警告

| 場景 | 後果 |
|---|---|
| `cacheKeyHeaders` 加 `User-Agent` | UA 變化萬千 → 每個 UA 一份 → **快取空間爆炸** |
| `cacheKeyHeaders` 加 `Cookie` | 每個 session 一份 → 同樣爆炸 |
| 不設 `ignoreQueryString` 而源站亂帶時間戳 query | 每次請求 key 都不同 → 永遠 MISS |

> Header 名稱**大小寫不敏感**,但**值大小寫敏感**。

## 五、源站 `Cache-Control` 互動

源站回的 header 影響 FurCDN 怎麼快取:

| 源站 Cache-Control | FurCDN 行為 |
|---|---|
| `public, max-age=3600` | 快取 1 小時 |
| `private` | **不快取**(個人資料,不應在 CDN) |
| `no-store` | **不快取** |
| `no-cache` | **不快取**(節點目前沒有條件式重新驗證,所以 `no-cache` 等同每次回源) |
| `s-maxage=600, max-age=60` | 以 `s-maxage` 為準(給共享快取用);`max-age` 只在沒有 `s-maxage` 時才參考 |

另外這幾種回應**一律不快取**:帶 `Set-Cookie` 的回應、`Vary` 含 `*` 或含「不在 `cacheKeyHeaders` 內」的 header(`Accept-Encoding` 除外)的回應;帶 `Authorization` 或一般 Cookie 的請求、以及客戶端自己送 `Cache-Control: no-cache` / `no-store` / `max-age=0` 的請求,會直接繞過快取。

### 規則 vs 源站 優先級

```
1. 規則 ttl = 0   → 不快取,每次回源(源站怎麼寫都沒用)
2. 規則 ttl > 0   → 以規則 TTL 為上限;源站的 s-maxage / max-age 比它短時採用較短者,
                    源站寫 private / no-store / no-cache 則不快取
3. 沒規則匹配     → 先看節點內建規則(圖片/CSS/JS/字體 7 天、html 5 分鐘、/api/* 不快取),
                    都沒中才用域名 cacheTime(預設快取時間)
4. cacheTime = 0  → 不快取

404 回應固定只快取 30 秒;但規則明確寫 `ttl=0` 時,404 也不快取。
```

實踐:**規則決定「最長快取多久」,源站只能讓它更短,不能讓它更長**;要延長就必須寫規則。

另外,只有**命中且勝出**的那條規則的 `cacheControl` 會寫進回應;沒命中的規則不影響回應。

## 六、刷新快取 [#purge]

規則的 TTL / 不快取設定**只在節點回源抓內容時**套用;已經快取的內容不會因為改了規則而消失。要讓規則變更立刻被看到,就得**刷新(purge)**對應的路徑。

刷新 = 把節點上已存的 entry 刪掉,下一個請求重新回源。兩種範圍:

| 範圍 | 說明 |
|---|---|
| 全域名 | 清掉該域名所有快取(舊行為,完全相容) |
| 選擇性 | 只清指定 URL / 目錄前綴 / 萬用字元命中的 entry |

### 儀表板

**域名編輯 > 基本設定 >「刷新緩存」**，開啟後預設「整個域名」，與 CLI 不帶選擇器及 SDK 的整站刷新相同。
切換「指定內容」後可同時填入三種選擇器，取聯集；每行一項：

| 範圍／欄位 | 填什麼 | 一行一筆的範例 |
|---|---|---|
| 整個域名 | 不用填；請求不帶 body | — |
| 指定 URL | 完整 URL 或以 `/` 開頭的路徑 | `https://example.com/a.css?v=1` |
| 目錄前綴 | 路徑前綴 | `/static/` |
| 萬用字元 | 路徑 glob,`*` 匹配任意字元(含 `/`) | `/assets/*.js` |

- 一次最多 **100 筆**(URL + 前綴 + 萬用字元合計),每筆最長 **2048 字元**
- 「指定內容」的三欄可以混用；「整個域名」只發送整站刷新，不會帶入選擇器
- master 直接向所有服務該域名的在線節點發出清除請求,通常 `<1 秒` 生效
- 每個節點刪除命中的磁碟 entry

### API

`POST /api/v1/domains/{id}/purge`,body 可以整包省略:

```bash
# 全域名刷新(等同舊行為,現有腳本不用改)
curl -X POST -H "Authorization: Bearer $FURCDN_API_KEY" \
  https://cdn.taipei/api/v1/domains/123/purge

# 指定 URL
curl -X POST -H "Authorization: Bearer $FURCDN_API_KEY" -H "Content-Type: application/json" \
  -d '{"urls": ["https://example.com/a.css?v=1", "/b.js"]}' \
  https://cdn.taipei/api/v1/domains/123/purge

# 目錄前綴
curl -X POST -H "Authorization: Bearer $FURCDN_API_KEY" -H "Content-Type: application/json" \
  -d '{"prefixes": ["/static/"]}' \
  https://cdn.taipei/api/v1/domains/123/purge

# 萬用字元
curl -X POST -H "Authorization: Bearer $FURCDN_API_KEY" -H "Content-Type: application/json" \
  -d '{"patterns": ["/assets/*.js"]}' \
  https://cdn.taipei/api/v1/domains/123/purge
```

三種選擇器可以**混用**(取聯集),但 `{"all": true}` 不能跟它們同時出現:

```bash
curl -X POST -H "Authorization: Bearer $FURCDN_API_KEY" -H "Content-Type: application/json" \
  -d '{"urls": ["/index.html"], "prefixes": ["/static/"], "patterns": ["/img/*"]}' \
  https://cdn.taipei/api/v1/domains/123/purge
```

| 選擇器 | 語意 |
|---|---|
| `urls` | 精確 URL。可寫完整 URL(host 必須等於該域名,否則 400)或以 `/` 開頭的 path。**query 算在匹配內**:`/a.css` 不會刷掉 `/a.css?v=1`;域名開了 `ignoreQueryString` 時才忽略 query。同一 URL 的所有快取變體(Vary 副本、GET 與 HEAD)一起清掉 |
| `prefixes` | 對路徑做純字串前綴比對,query 不參與。`/static/` 會清掉 `/static/a.js`、`/static/x/y.css`。也接受完整 URL 形式(只取路徑,host 同樣要等於該域名) |
| `patterns` | 對路徑做 glob,`*` 匹配任意字元(含 `/`),query 不參與,必須以 `/` 開頭。如 `/assets/*.js`、`/img/*` |

回應:

```json
{"ok": true, "mode": "all", "total": 5, "success": 5}
{"ok": true, "mode": "selective", "total": 5, "success": 5, "removed": 12}
```

- `mode`:`all`(全域名)/ `selective`(選擇性)
- `total`:服務該域名的在線節點數
- `success`:確認清除成功的節點數；選擇性刷新必須回傳合法的 `removed` 才算成功，單憑 HTTP 200 不算
- `removed`:成功節點刪掉的快取 entry 數，跨節點累加（同一 URL 在 3 個節點都有快取就算 3）；只有 `selective` 且至少一個節點成功時會出現。部分失敗時不包含失敗節點，不能當成全域總數；缺少回報的數量是未知，不是 0

控制面板、CLI 的 API Key／登入模式都只顯示一次節點結果與刪除筆數。沒有在線節點、部分失敗或缺少刪除數量時，不會顯示為全部成功；控制面板會保留對話框與失敗原因。

錯誤:`400` body 不合法(有 body 但沒有 all/urls/prefixes/patterns、`all` 與其他選擇器混用、host 不符、超過 100 筆、單筆超過 2048 字元、非字串…)、`401` 金鑰無效、`403` 域名不是你的、`429` 限速。格式一律 `{"error": "<訊息>"}`。

限速:全域名 **10 次 / 5 分鐘 / user**;選擇性 **60 次 / 5 分鐘 / user**。

Session 版端點 `POST /api/domains/{id}/purge`(dashboard 與 CLI 登入模式)body 完全相同,回應多一個 `message` 字串。完整規格見[開放 API](/api#purge)。

其他入口吃同樣的選擇器:

- **GitHub Action**:`urls` / `prefixes` / `patterns` 三個 input,一行一筆
- **SDK**:Go `PurgeCacheWith(ctx, id, PurgeOptions{URLs, Prefixes, Patterns})`、Java / Kotlin `purgeCache(id, PurgeOptions(...))`

> 不要過度刷新。全域名刷新後該域名所有節點全部 MISS,源站瞬時負載 ↑。
> 真要頻繁更新,把 TTL 改短,或者用選擇性刷新只清變動的那幾條路徑。

## 七、可直接貼進批量匯入的成套配方

### 7.1 靜態網站

```json
[
  { "name": "HTML 短 TTL", "matchType": "extension", "matchValue": "html,htm", "ttl": 300, "priority": 10, "enabled": true },
  { "name": "JS/CSS 30 天", "matchType": "extension", "matchValue": "js,css", "ttl": 2592000, "cacheControl": "public, max-age=2592000, immutable", "priority": 10, "enabled": true },
  { "name": "圖片 30 天", "matchType": "extension", "matchValue": "jpg,jpeg,png,webp,svg,ico,gif", "ttl": 2592000, "priority": 10, "enabled": true },
  { "name": "字體 1 年", "matchType": "extension", "matchValue": "woff,woff2,ttf,eot,otf", "ttl": 31536000, "cacheControl": "public, max-age=31536000, immutable", "priority": 10, "enabled": true }
]
```

配合「域名設定 > 忽略 Query String」即可用 `?v=hash` 隨時破快取。

### 7.2 SPA(Single Page App)

```json
[
  { "name": "首頁短 TTL", "matchType": "path", "matchValue": "/", "ttl": 300, "priority": 10, "enabled": true },
  { "name": "構建產物長 TTL", "matchType": "path", "matchValue": "/static/", "ttl": 2592000, "priority": 10, "enabled": true },
  { "name": "API 不快取", "matchType": "path", "matchValue": "/api/", "ttl": 0, "priority": 5, "enabled": true }
]
```

SPA 的 `index.html` 必須短 TTL,構建產物用 hash filename 可放長 TTL。

> `path=/` 現在**只**匹配根路徑 `/`,不是「全部路徑」;SPA 的深層路徑(如 `/about`)不會命中它,那些由域名 `cacheTime` 決定,或另外補一條 `extension: html` 規則。這份配方裡 `/`(10)、`/static/`(10)、`/api/`(5)三者互不重疊,行為確定。

### 7.3 WordPress / 動態 CMS

```json
[
```

### 7.4 OSS / 對象儲存圖床

```json
[
  { "name": "全部資源長 TTL", "matchType": "all", "ttl": 2592000, "cacheControl": "public, max-age=2592000, immutable", "priority": 10, "enabled": true }
]
```

OSS 內容不變,**極長 TTL**。配合 `ignoreQueryString=true` + presigned URL,流量可以做到 99% 命中率。

### 7.5 即時新聞

```json
[
  { "name": "首頁 1 分鐘", "matchType": "path", "matchValue": "/", "ttl": 60, "priority": 10, "enabled": true },
  { "name": "文章 10 分鐘", "matchType": "path", "matchValue": "/news/", "ttl": 600, "priority": 10, "enabled": true },
  { "name": "圖片 1 天", "matchType": "extension", "matchValue": "jpg,png,webp", "ttl": 86400, "priority": 6, "enabled": true },
  { "name": "API 不快取", "matchType": "path", "matchValue": "/api/", "ttl": 0, "priority": 5, "enabled": true }
]
```

圖片規則用 `priority: 6`:排在 `/news/` 前綴(10)之前(否則新聞配圖會先被 `/news/` 命中,只拿到 10 分鐘),但仍排在「API 不快取」(5)之後(`/api/` 底下的圖也必須回源)。

兼顧即時性 + 性能,配合[選擇性刷新](#purge)應對重大新聞(只刷被改動的那幾條路徑,不用全站清空)。

### 7.8 規則精修:特定文件覆蓋通用規則

想 `/static/v1/critical.js` 走 1 小時 TTL 而其他 `/static/*.js` 走 30 天?
**用更小的 priority 覆蓋:**

```json
[
  { "name": "Critical JS 短 TTL", "matchType": "path", "matchValue": "/static/v1/critical.js", "ttl": 3600, "priority": 5, "enabled": true },
  { "name": "其他 JS 長 TTL", "matchType": "extension", "matchValue": "js", "ttl": 2592000, "priority": 10, "enabled": true }
]
```

## 八、JSON 模式常見錯誤

| 錯誤訊息 | 原因 |
|---|---|
| `JSON 格式錯誤: Unexpected token` | 多了/少了逗號、用了 trailing comma、雙引號漏掉 |
| `頂層必須是規則物件` | 單規則編輯時頂層必須是 `{...}`;陣列請走批量匯入 |
| `匹配類型無效` | `matchType` 不在 `extension / path / contentType / all` 之中 |
| `匹配值必填` | `matchType` 不是 `all` 時 `matchValue` 必須有值 |
| `TTL 不合法` | 必須是 0–315360000 的整數(10 年上限) |
| `已存在相同匹配規則` | 後端去重:同 `(matchType, matchValue)` 已有規則;改 matchValue 或刪舊的 |

## 九、故障排查

### 永遠 MISS,沒命中

1. **域名 cacheEnabled 開了嗎**?域名編輯 > 緩存 > 緩存總開關
2. **規則 enabled=true 嗎**?且 priority 沒被前面的 `ttl=0` 規則蓋掉?
3. **源站 `Cache-Control: no-store` / `private`** 而你沒寫規則覆寫?寫規則 `ttl > 0` 強制
4. **query 變化**:沒設 `ignoreQueryString` 而每次 query 都不同
5. **`Vary: *`**:源站回了 `Vary: *` 等同不可快取

### 快取了不該快取的內容

1. 該路徑有規則 ttl > 0 嗎?改成 0
2. 登入態頁面應該有 `Cache-Control: private`,源站沒設就加規則 ttl=0
3. **緊急刷快取**:點「立即刷新緩存」;只有少數路徑中標時,用「指定 URL / 目錄前綴」只刷那幾條(見[刷新快取](#purge))
4. 改完規則**一定要刷新**對應路徑,規則不會回頭動已快取的內容

### 多語言頁面只看到一種語言

- 沒設 `cacheKeyHeaders=["Accept-Language"]`
- 第一個訪問的人是哪種語言,後面所有人都看到那種

### 改了源站但 CDN 還是舊內容

- TTL 還沒到 → 等,或直接刷新那幾條 URL / 前綴(見[刷新快取](#purge))
- 規則 `cacheControl` 設了長 max-age 也覆寫到 response,**用戶端瀏覽器**也快取了
- 改規則的 cacheControl,新請求才會拿短 max-age;舊請求等舊 max-age 過期

### 開了 ignoreQueryString 後 SEO 受影響?

- 不會。SEO 看的是源站 + URL 結構,跟 CDN 快取鍵無關
- 只要源站對相同 query 永遠返回同樣內容,`ignoreQueryString` 安全

## 十、進階:Cache-Control 透傳

如果你的源站本身就有完整的快取策略(例如 `Cache-Control: public, max-age=86400, s-maxage=604800`),**不需要寫 FurCDN 規則**:

1. 域名 `cacheEnabled=true`
2. 域名 `cacheTime` 設一個合理 fallback(如 60 秒)
3. **不寫任何 cacheRule**(或只寫 `path=/api/` ttl=0 排除 API)

FurCDN 會直接讀源站的 `s-maxage`(優先) / `max-age`,完整尊重源站策略。

優點:**單一事實來源**,改源站 header 即可即時生效,不需動 CDN 設定。
